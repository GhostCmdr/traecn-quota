# 凭证取源（为什么不留明文兜底）

从 README 移出的设计说明，用户不需要读，改这块代码前需要读。

## 兜底顺序的取舍

凭证只取两个来源：设置项 `manualToken`（收进 `SecretStorage`）与已登录的 Trae 客户端本地登录态（`%APPDATA%\<客户端>\User\globalStorage\storage.json` 里的加密登录态）。两者都拿不到就直接报「未找到登录态」，**不再退到 `~/.trae-cn/trae-jwt-token` 那类明文文件**。

原因：那是 SOLO 运行时的身份 JWT，实测打积分接口一律 401。用它兜底只会把「没登录」伪装成「认证失败」，用户看到的错误和真实原因无关，反而更难排查。宁可少一个来源，也不要一个会误导人的来源。

## 为什么删除保管箱必须走命令

只把设置项 `traecnquota.manualToken` 删空**不会**清除保管箱里那份。同 profile 的多个窗口能互相看到设置变更，若靠「设置项变空」来推断用户想删除，会误删别的窗口刚存进去的凭证。所以提供显式命令 **TraeCN Quota: 清除保管箱里的手动 Token**，删除动作只能由命令触发。

## hostOverride 为什么收窄

出于凭证安全只接受默认端口上的 `https://api.trae.cn`，其他值（含任意 `*.trae.cn` 子域）一律忽略并回落。配置项本身是明文可读、可被 Settings Sync 同步的，不能让它成为把 token 发往任意地址的通道。

## 设置界面排序

各项按名称字母序排列是 VSCode 设置界面的固定行为，插件无法指定先后，不要试图用改 category 顺序来绕。
